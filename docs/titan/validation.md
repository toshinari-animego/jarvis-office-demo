# TITAN 新デザイン試験導入

判定：**本人の実機評価用の比較試作。正式採用・v0.4完成確定・mainへのマージは保留。**

対象は `toshinari-animego/jarvis-office-demo` の既存 `feature/office-v0.4` とDraft PR #1のみ。開始点は `7be57d02c5dca98730949e4bc2ba1f14aace7f98`。旧TITANの実装を含む `sprites.js` と、状態管理の `simulation.js` は変更していません。BOLT・SCOUTのデザイン変更もありません。

## 使用画像と素材

添付された生物型TITANのシートを確認し、同じ絵柄の保存済み元PNG「タイタン キャラクターコンセプトシート.png」（1448×1086）から正面図を切り出しました。共有リンク自体の内容は取得できなかったため、リンク先を確認できたとは扱いません。

元PNG SHA-256：`740b1c3fde71f365ed29fc61fff93c691af439168bad1938c86d6d4f3e0707e0`。

`assets/titan/manifest.json` に元画像・切り出し座標・加工範囲を記録。`scripts/prepare-titan.py` に手動マスクを保存しています。シート全体を貼るのではなく、頭／胴体／左右の腕／左右の脚を個別の透過PNGに分離。ネイビーの背景の縁を整理し、0.35pxの境界処理を行いました。AIによる再生成・欠損部分の生成・有料処理は実施していません。元の肌・髪・筋肉・装備・三角形コアの画素を使っています。

各素材は265×243 RGBA。6パーツの合計は126,135バイト（圧縮PNG）。`assembled.png` と分離確認画像はレビュー用で、通常画面では読みません。原画内の小さな正面図が元なので、巨大な表示用の高解像度キャラクター素材ではありません。64〜100 CSS pxのオフィス表示を前提にしています。

## 実装と比較方法

- `titan-rig.js`：6枚をSVGのグループで組み立て、肩・首・腰の回転中心を指定。
- `app.js`：表示だけの `setTitanSkin()`。状態、要求、成果物の所有権、履歴、カウンター、時計を変更せずリグを切り替える。停止中も同じ位置・姿勢で比較できる。
- 旧TITAN：既存 `sprite('titan')` をそのまま使用。新TITANを外して復元可能。
- `?titan=old`：旧デザインを初期表示。指定なしは新デザインの試験表示。
- レビュー画面：旧／新ボタン、幅変更、待機・歩行・受け取りの停止、全体画面への復帰を用意。ポーズ比較は同じ一時停止中に表示を切り替えたもの。

新TITANは同じキャラクター枠で描画し、幅広い筋肉のシルエットを優先。原画の縦横比は維持し、基本枠内のSVG表示倍率と影を調整。3体比較で小さく見えた初稿から新TITANを約18%拡大し、横幅のある体格を優先しました。接近間隔は新旧共通で基本幅の1.09倍に設定し、切り替えで位置が変わらないようにしています。デスクやBOLT・SCOUTの配置と色は変更していません。

## 動きの範囲

| 動き | 実装 |
|---|---|
| デスク待機／作業 | 元の原画を使い、共通時計による胴体の上下・頭と腕の小動作を接続。 |
| 呼びかけに顔を上げる | 頭パーツの回転と上方向への移動。 |
| 予備動作・立ち上がり | 沈み込み・重心移動・スケール変化を継承。 |
| 重量歩行 | 短い脚の交互の回転、体の左右の揺れと上下、重いテンポ。成果物を持つ間は両腕を寄せる。 |
| 両手受け取り | 両肩から腕を前へ寄せる可動。受領時点で成果物の所有権を切り替える。 |
| デスク復帰・再作業 | 既存タイムラインを維持。 |
| 完了の喜び | 上下の弾み・小さな傾き・片腕を上げる動作。 |
| 目・口の独立した表情変化 | **未実装**。原画の顔を保持。旧SVGの瞬き・口変化を新画像へ再現したとは扱わない。 |
| 肘・指の個別関節／側面・背面歩行 | **未実装**。正面6パーツの2D可動であり、3Dの振り向きや完全な歩行原画ではない。 |

## 検証

最終の結果は同じディレクトリの `unit-tests.txt`、`browser-ui-tests.txt`、`viewports.json`、`browser-audit.json` に記録します。

- Nodeの既存コアテスト24件：成功。6方向、停止、リセット、連打、30分相当の模擬時間を検査。実時間30分の性能試験ではありません。
- 新TITANの表示、旧デザインへの復元、新旧切り替え時の状態不変：Chromeで確認。
- 全6方向のUIテスト：各方向で停止／再開、手動操作30回連打、新旧20回切り替え、受領と帰還と作業開始、3体のみ表示を確認。
- BOLTとSCOUT：停止中に新旧を繰り返してもactorのSVG内容が変化しないことを確認。実装ファイルも差分なし。
- PNG：6枚すべて265×243 RGBA、透明と不透明の画素を持つことを確認。
- 画面幅：320／375／390／768／1024／1156 CSS pxで横はみ出しなし。新旧ボタンを含む操作ボタン・選択欄は44px以上。
- 画像読み込み：6 PNGを含む同一サイトの静的リソース11件でHTTP 200。外部リソース0件、アプリ由来ログエラー0件（観測範囲）。
- 通信・アプリログ：添付の測定記録に基づく。Resource Timingは観測できたリソースだけであり、端末全体の通信キャプチャではありません。

**実機Safari／WebKitシミュレーターの確認、iPhone／iPadのFPS・発熱・GPU負荷は未確認。** Chromeの可変幅表示を実機の成功と混同しません。PNGの展開画素量は6枚で約1.55MB相当のRGBA（計算値）ですが、ブラウザー全体の実メモリー量を示すものではありません。

## 安全条件と推奨判断

main・現行v0.3・GitHub Pages設定を維持。本番JARVIS、他リポジトリ、Cloudflare本番、Secrets、実業務データにはアクセスしていません。追加の生成API・有料サービス・依存インストールなし。
